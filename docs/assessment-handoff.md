งานนี้อยู่ในบรานช์ `sky` ของ `chokunkie02/little_speech` ฐานเว็บของโชกุนคือ `9b33d85` ณ 16 พฤศจิกายน 2026

**เป้าหมายรอบนำเสนอ**

ให้แอดมินระบบกำหนดวิธีตรวจและเกณฑ์ร่วมกัน ห้องฝึกเลือกวิธีตามกิจกรรม เด็กหรือผู้ปกครองเห็นผลหลังส่งตรวจ และครูหรือผู้ปกครองอ่านผลในความก้าวหน้าและรายงานตามสิทธิ์เดิม

> **อัปเดต 18 พ.ย. 2026:** สมัคร Azure ไม่สำเร็จ ทีมจึงเปลี่ยนมาใช้ **OpenAI** เป็นบริการตรวจเสียงหลัก (`ASSESSMENT_SPEECH_PROVIDER=openai` เป็นค่าเริ่มต้น) โดยใช้ API key ของพี่บาส ตัวเชื่อม Azure ยังอยู่ครบและสลับกลับได้ด้วย env ดูหัวข้อ **ตั้ง OpenAI** ด้านล่าง

ค่าเริ่มต้นปิดการประเมินเสียงอัตโนมัติจนกว่าจะใส่คีย์และเผยแพร่เกณฑ์ที่เปิด AI ข้อเลือกตอบตรวจจากเฉลยได้จริง และการตรวจของผู้ใหญ่บันทึกเข้าระบบกลางได้ ชุดตรวจทดสอบ Azure และ OpenAI ด้วย response จำลอง การยืนยันผลเสียงจริงต้องทำหลังใส่คีย์

**ลำดับการใช้งาน**

1. เข้า `/platform` แล้วเปิด **ศูนย์ประเมินการเรียนรู้** หรือเปิด `/platform/assessment`
2. ตั้งชื่อชุดเกณฑ์ วิธีตรวจของแต่ละขั้น คะแนนขั้นต่ำ ความครบของข้อความ ความมั่นใจการรู้จำ และช่วงความยาวเสียง
3. ลองคะแนนใน **ลองเกณฑ์ด้วยคะแนนตัวอย่าง** ผลจำลองส่วนนี้อยู่เฉพาะหน้าจอแอดมิน
4. กด **บันทึกฉบับร่าง** แล้วกด **เผยแพร่เป็นเวอร์ชันใหม่** ผลประเมินครั้งถัดไปใช้ snapshot ใหม่
5. บัญชีผู้ปกครองเลือกเด็กและเปิด `/training` ทำข้อเลือกตอบหรืออัดเสียงพูด
6. เมื่ออัดเสียงจริงและเปิด AI แล้ว ให้ยินยอมส่งคลิปและกด **ส่งเสียงให้ AI ตรวจ** ผลจาก Azure ถูกเก็บพร้อมเลขเวอร์ชันเกณฑ์
7. กด **บันทึกการลองทำ** แล้วดูผลในสรุปหรือรายละเอียดรอบ ข้อพูดยังมีการตรวจยืนยันของผู้ใหญ่แยกต่างหาก
8. เมื่อผู้ใหญ่ตรวจรอบที่จบแล้ว ระบบส่งผลยืนยันเข้าศูนย์กลาง โดยเก็บคำแนะนำเดิมจาก Azure ไว้ด้วย
9. หน้า `/progress` และ `/report` แสดง **ผลประเมินจากศูนย์กลาง** พร้อมแหล่งที่มาและเวอร์ชัน ผลส่วนนี้เป็นประวัติการลองตรวจซึ่งอาจเกิดก่อนจบรอบ

ใช้ Supabase ผ่าน Docker ในเครื่องตาม workflow ของทีม ตั้ง `NEXT_PUBLIC_STORAGE_PROVIDER=supabase`, URL/anon key ของฐานในเครื่อง และ `SUPABASE_SERVICE_ROLE_KEY` ฝั่งเซิร์ฟเวอร์ ในรอบที่พัฒนานี้ใช้ project `little-speech-board` พอร์ต API 55321 และ PostgreSQL 55322

ฝั่งเซิร์ฟเวอร์ตรวจ bearer token ด้วย `auth.getUser` ทุกครั้ง การแก้เกณฑ์ตรวจ `app_metadata` จากผู้ใช้ที่ยืนยันแล้ว ก่อนใช้ service role บันทึกข้อมูล ส่วนการประเมินและอ่านผลใช้ฟังก์ชัน `can_access_learning_results` ของโชกุน RLS อนุญาตให้บัญชีที่มีสิทธิ์ดูเด็กอ่านผลได้ และปิดการเขียนคะแนนหรือเกณฑ์โดยตรงจาก browser

ฉบับร่างใช้ revision เพื่อป้องกันการเขียนทับจากสองหน้าต่าง การเผยแพร่ล็อกแถวแล้วเพิ่มเวอร์ชันใน transaction ผลเก่าอ้าง version เดิม การกดใช้เกณฑ์เก่าในหน้าแอดมินนำ config มาเป็นร่างซึ่งต้องบันทึกและเผยแพร่ใหม่

แต่ละคำขอใช้ UUID และ SHA-256 ของบริบทกับเสียง คำขอซ้ำที่เนื้อหาเดิมคืนผลเดิม คำขอที่ใช้ UUID เดิมกับข้อมูลอื่นถูกปฏิเสธ ฝั่งฐาน serialize การ claim ต่อบัญชี จำกัด 12 คำขอใหม่ต่อนาที และรอคำขอที่กำลังตรวจ เสียงค้างระหว่างตรวจเกินช่วงรอให้ผู้ใช้เริ่มการอัดใหม่

**ตั้ง OpenAI (บริการหลักตอนนี้)**

1. ขอให้พี่บาสสร้าง API key **แยกสำหรับโปรเจกต์นี้** ใน OpenAI และตั้งวงเงินรายเดือน ส่งคีย์ทางช่องส่วนตัว ไม่ส่งในกลุ่มแชทหรือ commit ลง Git
2. ใส่คีย์หลัง `ASSESSMENT_OPENAI_API_KEY=` ใน `.env.local` (ไม่มีเครื่องหมายคำพูดหรือช่องว่าง) แล้วรัน `npm run assessment:check-openai` สคริปต์บอกว่าคีย์ใช้ได้ไหมและเข้าถึงโมเดลถอดเสียงตัวไหนได้ โดยไม่พิมพ์คีย์ออกมา
3. ระบบประเมินใช้ตัวแปรชื่อของตัวเอง ไม่ใช้ `OPENAI_API_KEY` เพราะเครื่องนักพัฒนามักตั้ง `OPENAI_API_KEY` ไว้ใน Windows สำหรับเครื่องมืออื่น (เช่นคีย์ OpenRouter `sk-or-…`) และตัวแปรของเครื่องจะทับ `.env.local` ใน Next.js จึงไม่ต้องลบตัวแปรนั้น คีย์ OpenRouter ใช้กับระบบนี้ไม่ได้ ต้องเป็นคีย์ของ OpenAI โดยตรง
4. เปิด Next.js ใหม่ เข้า `/platform/assessment` ต้องเห็น **บริการ AI ตรวจเสียง: OpenAI · ตั้งค่าแล้ว** เปิด AI ในร่าง บันทึก และเผยแพร่
5. ทดสอบด้วยบัญชีผู้ปกครองตามข้อ 5–6 ของหัวข้อ Azure ด้านล่าง

วิธีตรวจของ OpenAI ต่างจาก Azure ต้องอธิบายให้ทีมเข้าใจตรงกัน

- ส่งคลิป WAV ไป `POST /v1/audio/transcriptions` ด้วย `gpt-4o-transcribe`, `language=th`, `temperature=0`, `include[]=logprobs` เปลี่ยนโมเดลได้ด้วย `OPENAI_ASSESSMENT_TRANSCRIBE_MODEL`
- **ไม่ส่งคำเป้าหมายไปกับคำขอ** เพราะถ้าบอกโมเดลล่วงหน้า โมเดลจะถอดเป็นคำเป้าหมายแม้เด็กพูดไม่ตรง ระบบ legacy `/api/speech/evaluate` ทำแบบนั้นอยู่และมีปัญหาคะแนนสูงเกินจริง
- เซิร์ฟเวอร์เทียบข้อความที่ได้ยินกับคำเป้าหมายระดับตัวอักษรไทย (ตัด space และเครื่องหมายวรรคตอน) ได้ `accuracy` = ความตรงทั้งข้อความ, `completeness` = ส่วนของคำเป้าหมายที่พบตามลำดับ และ `score` = 60% accuracy + 40% completeness แล้วใช้เกณฑ์ pass/practice/completeness เดิม
- `confidence` = ค่าเฉลี่ยเรขาคณิตของความน่าจะเป็นราย token จากโมเดล ถ้าโมเดลไม่ส่งค่ามา (เช่น `gpt-transcribe`) ค่าเป็น 0 และทุกผลจะไปรอผู้ใหญ่ตรวจ
- สิ่งที่วัดได้คือ **"เด็กพูดคำที่ถูกหรือไม่"** ไม่ใช่ความชัดของการออกเสียง เด็กที่ออกเสียงเพี้ยนเล็กน้อยอาจยังผ่านถ้าโมเดลเดาคำได้ และการพูดซ้ำ ("ปู ปู") จะได้ "ฝึกต่อ" เพราะมีคำเกิน จึงยังต้องให้ผู้ใหญ่ยืนยันคู่กัน
- ค่า `rule.mode` ในฐานยังเก็บเป็น `"azure"` ซึ่งหมายถึง "AI ตรวจเสียง" ไม่ว่าใช้บริการใด เพื่อไม่ต้อง migrate เกณฑ์ที่เผยแพร่แล้วและเกณฑ์โรงเรียน ส่วนผลใหม่เก็บ `source: "openai"`
- OpenAI แจ้งว่าไม่นำข้อมูลจาก API ไปเทรนโดยค่าเริ่มต้น แต่ยังต้องขอความยินยอมก่อนส่งเสียงเด็กจริง และทบทวนเงื่อนไขการเก็บข้อมูลของบริการก่อนใช้นอกการทดสอบ

**ทางเลือก: ตั้ง Azure**

ตั้ง `ASSESSMENT_SPEECH_PROVIDER=azure` แล้วทำตามขั้นตอนนี้

1. สร้างบัญชี Azure และ subscription ที่รองรับ Speech การสมัครอาจต้องยืนยันตัวตนและวิธีชำระเงิน เจ้าของบัญชีเป็นผู้ดำเนินการส่วนนี้
2. สร้าง **Speech resource** แล้วจด Region กับ Key จากหน้า **Keys and Endpoint**
3. ตั้งค่าฝั่งเซิร์ฟเวอร์ใน `.env.local` ตัวอย่างโครงสร้างอยู่ใน `.env.example`

```dotenv
AZURE_SPEECH_KEY=ใส่คีย์ในเครื่อง
AZURE_SPEECH_REGION=southeastasia
# อีกทางเลือกใช้ endpoint ของ resource
# AZURE_SPEECH_ENDPOINT=https://your-resource.cognitiveservices.azure.com
```

4. เปิด Next.js ใหม่ แล้วเข้า `/platform/assessment` สถานะ **ตั้งค่าการเชื่อมต่อแล้ว** หมายถึงมีค่าที่ตั้งไว้ ต้องส่งเสียงจริงเพื่อยืนยันการเชื่อมและสิทธิ์ resource
5. เปิด AI ในร่าง บันทึก และเผยแพร่ จากนั้นใช้บัญชีผู้ปกครองเลือกโจทย์พูดตามในเสียง ป ก ม
6. ทดสอบพูดตรงคำ พูดคำอื่น เสียงเงียบ และการปิดเครือข่าย แล้วจดผลเทียบกับผู้ใหญ่ก่อนวันนำเสนอ

คีย์ใช้ผ่าน environment ฝั่งเซิร์ฟเวอร์ หน้าแอดมินแสดงเพียงสถานะ ชื่อ region และคู่มือ การปิด AI ทำให้คำขอใหม่ใช้ผู้ใหญ่ตรวจ ผู้ใช้ต้องอัดใหม่เพื่อส่งคลิปใหม่เมื่อเปิด AI

**รายละเอียดผลประเมินและข้อจำกัดที่ทีมต้องทราบ**

- ใช้ Azure Short Audio REST, ภาษา `th-TH`, `Granularity=Word` และ `Dimension=Comprehensive` เสียง PCM mono 16 kHz/16-bit สูงสุด 30 วินาที
- ใช้ `PronScore`, `AccuracyScore`, `CompletenessScore` และ confidence ของการรู้จำตาม response ที่ตรวจโครงสร้างแล้ว คะแนนความถูกต้องในรอบนี้เป็นผลรวมของข้อความอ้างอิง การบอกข้อผิดพลาดระดับพยัญชนะเฉพาะต้องพัฒนาและทดสอบเพิ่ม
- ค่าเริ่มต้น pass 75, practice 55, completeness 70 และ confidence 0.6 เป็นค่าทดลองสำหรับ POC ให้ผู้เชี่ยวชาญช่วยปรับจากข้อมูลจริง
- คะแนนรวมสูงยังต้องผ่าน accuracy และ completeness ขั้นต่ำด้วย ความมั่นใจการรู้จำต่ำส่งให้ผู้ใหญ่ตรวจ
- เมื่อไม่มีคีย์ เปิดบริการไม่ได้ เสียงเงียบ/สั้น/ยาวเกิน หรือ provider ตอบไม่ครบ จะได้สถานะ unavailable/needs_review พร้อมเหตุผล และไม่มีคะแนนเสียงที่สร้างขึ้นมาแทน
- RMS เป็นการตรวจพลังงานเสียงเบื้องต้น การยืนยันว่าเป็นคำพูดที่ใช้ประเมินได้ขึ้นกับผลบริการและการทดสอบเพิ่มเติม
- คลิปอยู่ในเบราว์เซอร์และหน่วยความจำของเซิร์ฟเวอร์ระหว่างตรวจ ผลกลางเก็บข้อความ คะแนน แหล่งที่มา และเวอร์ชัน ทีมต้องตรวจเงื่อนไขการประมวลผลของ Azure กับความยินยอมก่อนเก็บข้อมูลเด็กจริง
- การตรวจของผู้ใหญ่เก็บเป็นอีกช่องหนึ่งและไม่เขียนทับผลบริการ ข้อสังเกตอิสระจากช่อง review note ของห้องฝึกยังเป็นข้อมูลในเครื่องตามโฟลว์เดิม
- ผลในห้องฝึกยังเก็บที่เบราว์เซอร์ ส่วนการลองตรวจที่ส่งสำเร็จถูกเก็บในฐานกลางทันที จึงอาจมีประวัติการลองตรวจของรอบที่ยังทำไม่จบ
- อาจมีผลกำลังตรวจที่ค้างจาก server crash ให้เริ่มการอัดใหม่ รายการค้างถูกแยกจากผลที่ตรวจเสร็จ

**แผนก่อนวันนำเสนอ**

| ลำดับ | สิ่งที่ต้องส่งมอบ | สถานะรอบนี้ |
| --- | --- | --- |

| 2 | เชื่อมห้องฝึกกับการตรวจเฉลย การส่งเสียง และผลของผู้ใหญ่ | ทำแล้ว |
| 3 | ผลตามสิทธิ์เด็กในความก้าวหน้าและรายงาน | ทำแล้ว |
| 4 | ตัวเชื่อม OpenAI และใส่ `ASSESSMENT_OPENAI_API_KEY` (Azure สมัครไม่สำเร็จ) | ตัวเชื่อมทำแล้ว รอคีย์จากพี่บาส |
| 5 | ตรวจเสียงจริงของ ป ก ม และเลือกชุดโจทย์สาธิต | ทำต่อหลังข้อ 4 |
| 6 | เทียบผลกับผู้เชี่ยวชาญและซ้อมนำเสนอ | ทำต่อหลังข้อ 5 |

**การตรวจสอบ**

```powershell
npm run assessment:test
npm run assessment:test-stages
npm run learning:test
npx tsc --noEmit
npm run build
```

ชุด `assessment:test-stages` เรียก route จริง `POST /api/assessment/evaluate` ครบทั้ง 432 กิจกรรม โดยแทนเฉพาะฐานข้อมูล (`scripts/assessment/fakes/supabase.mjs` ทำงานแบบเดียวกับ `claim_assessment` จริง) และการเรียก OpenAI ด้วยของจำลอง แล้วเทียบวิธีตรวจของแต่ละขั้นกับตารางออกแบบ 12 ขั้นที่เขียนไว้ในสคริปต์ ครอบคลุมพูดถูก พยัญชนะผิด พูดซ้ำ ความมั่นใจต่ำ เสียงเงียบ/สั้น OpenAI ตอบ 401/429/500 เครือข่ายล่ม ไม่มีคีย์ คีย์ OpenRouter การกดซ้ำ สิทธิ์ 401/403 จำกัด 12 ครั้งต่อนาที และเกณฑ์รายโรงเรียน ผลรายขั้นเก็บที่ `.learning-runtime/assessment-stages/report.json`

**Agent Tester:** `.claude/agents/assessment-tester.md` เป็น subagent ของ Claude Code สั่งได้ด้วยข้อความเช่น "ใช้ assessment-tester ทดสอบระบบประเมิน" agent รันชุดตรวจตามลำดับชั้น (unit → stage matrix → static → เช็กคีย์ → เบราว์เซอร์เมื่อขอ) และรายงานผลรายขั้นเป็นภาษาไทย ไม่แก้โค้ดและไม่ commit การเรียก OpenAI จริงทำเฉพาะเมื่อสั่งชัดเจน ส่วนการทดสอบหน้าเว็บใช้ `.claude/launch.json` (`next-dev`) กับบัญชี `*@speechadventure.test` จาก `scripts/dev/seed-dev-accounts.mjs` บน Supabase ในเครื่องเท่านั้น

ชุด `assessment:test` ตรวจการหาเกณฑ์ครบ 432 กิจกรรม ร่างผิดรูปแบบ เกณฑ์ที่ขัดกัน ผล confidence ต่ำ WAV ปลอม/เสียงเงียบ การอ่าน Azure REST response การให้คะแนนจากข้อความที่ OpenAI ถอดได้ ความมั่นใจจาก logprobs คำขอที่ไม่ส่งคำเป้าหมาย การสลับบริการ และการย้ายประวัติเดิม โดยทดสอบ Azure และ OpenAI ด้วย fixture

ทดสอบ API เพิ่มกับบัญชีสมมุติใน Docker ครอบคลุมผู้ใช้ทั่วไปแก้เกณฑ์ไม่ได้ การแก้ร่างชนกัน การเผยแพร่เพิ่ม version การปฏิเสธเปิด AI เมื่อไม่มี key การตรวจ choice ที่เซิร์ฟเวอร์ การกดซ้ำ การเข้าถึงผลเด็กและ RLS รวมถึงการยืนยันของผู้ใหญ่ ส่วน UI ทดสอบแอดมินและผู้ปกครองผ่านเบราว์เซอร์ด้วยข้อมูลสมมุติ

**วิธีรวมงานกับการแก้ของโชกุน**

โค้ดส่วนใหญ่แยกอยู่ใน `src/lib/assessment`, `src/components/assessment`, `src/app/api/assessment` และหน้าใหม่ `src/app/platform/assessment` จุดที่ต้องดูตอนรวมคือปุ่มทางเข้าที่ `src/app/platform/page.tsx`, ส่วนอัดและบันทึกใน `LearningStudio.tsx`, `Attempt.assessment`, `useStudioResultSync.ts`, และ `LearningResults.tsx`

เมื่อโชกุนอัปเดต main ให้รวมไฟล์ใหม่ก่อน แล้วเทียบจุดอัดเสียง/บันทึก attempt กับหน้าแสดงผล ใช้ `getStages` จากหลักสูตรจริงเสมอ ถ้าเปลี่ยน stage ID ให้ปรับ `STAGE_DEFINITIONS`, เกณฑ์ในฐานผ่าน migration และชุดตรวจควบคู่กัน

**แหล่งอ้างอิงการออกแบบ**

- เอกสาร Microsoft ระบุภาษาไทยใน Pronunciation Assessment และอธิบายข้อจำกัดของรายละเอียดตาม locale [Language support](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/language-support?tabs=pronunciation-assessment#pronunciation-assessment) · [Supported features](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/how-to-pronunciation-assessment#supported-features-per-locale)
- ข้อกำหนด WAV, เวลาอัด, header และ response ที่ใช้ในตัวเชื่อม [Short Audio REST](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/rest-speech-to-text-short)
- การวัดคำเดี่ยว การเลียนเสียง และการพูดต่อเนื่องเป็นคนละบริบทที่ต้องดูร่วมกัน [ASHA](https://www.asha.org/practice-portal/clinical-topics/articulation-and-phonology/)
- การประเมินระดับเสียงและข้อมูลกำกับสำคัญต่อการตรวจเสียงเด็ก [Lin et al., 2024](https://www.isca-archive.org/interspeech_2024/lin24k_interspeech.html)
